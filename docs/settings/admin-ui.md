# moks-cms web admin: settings inventory

Read-only inventory of every setting an admin sees and changes in the moks-cms admin (`/admin`), where it is stored, who reads it, and what is wrong with the current arrangement. Source: moks-cms at `5645bd6` (2026-11-26). Environment variables are covered separately; they appear here only where a UI field overrides or is overridden by one.

**Counting rule.** One table row is one control, or one group of sibling controls that share a storage path and behaviour (for example "Topic / Article type / Date / Reading time"). Repeated structures are one row: menus, homepage sections, footer columns, the 4 Hire-me offers, per-provider and per-model rows of the LLM providers card, schedules. Records such as users, API keys and schedules are listed once each where they work like settings. Rows generated from a registry (runtime-settings `GROUPS`, the SEO settings document `DEFAULT_SEO_SETTINGS`, the agent's `admin_settings` registry and `news` `JOB_SETTING_GROUPS`) list one row per field.

**Column legend**
- **Storage**: the `setting` table row (`setting \`key\``), `site_config` (Appearance draft and published), another table, a cookie, or "agent" (saved in the seo-agent through its API and not kept in the CMS).
- **Live/restart**: whether a save takes effect without a restart, and how.
- **Audit**: whether saving writes an `audit_log` entry, the action name, and where it is written.
- **Guide/search**: **Ref** means the field is listed in the User manual's Settings reference (`src/lib/user-guide-settings.ts` `settingsReference()`, searchable under User manual → Settings). **Prose only** means the area is described only in guide articles (`src/lib/user-guide.ts`). **—** means it is in neither. The admin menu filter (`lib/admin-menu.ts` `filterMenu`) searches page names only, never fields.
- **(no hint)** after a label: the form shows no help text for the field. A placeholder alone does not count as a hint.
- Paths are relative to the repository root. `file:line` was read in the code. Anything marked *unverified* was inferred and not confirmed.

## 1. Current admin menu tree

Source: `src/lib/admin-menu.ts:48-148` (groups, order, in-group titles), `src/app/admin/layout.tsx:38-125` (who sees what, long labels) and `src/lib/modules.ts:44-78` (AI & SEO appears only while the SEO agent module is installed). Items marked (admin) are for admins only; authors see Posts, Media, Pages, Comments → All comments, Practice and "Your account" (Profile, API keys).

- **Dashboard** → Home `/admin`
- **Posts**
  - All posts `/admin/posts`; Add new post; Categories; Tags
  - *Editorial*: Editorial calendar `/admin/calendar` (admin); Review queue `/admin/review` (admin)
  - Promotion `/admin/promotion` (admin). Its last section, **Promotion settings**, holds 9 settings.
- **Media** → Library `/admin/media`. It holds no settings; the image display settings are in Appearance → Media.
- **Pages** → All pages; Add new page; **Hire me page**. "Hire me page" is `/admin/appearance?section=hireMe`, a section of the Appearance editor.
- **Comments** → All comments; Messages (admin); **Bookings** `/admin/bookings` (admin). Bookings has the "Cal.com bookings" settings card.
- **AI & SEO** (admin; drawn only while the SEO agent is installed. Every page under it is wrapped in `ModuleGate`, so it is unreachable while the agent is not installed)
  - *Flows & crews*: CrewAI console `/admin/crewai`; Flows `/admin/crewai/flows`, with a **Schedules** button to `/admin/crewai/schedules` (not in the menu) and the content-flow detail page that holds the "Content flows on" switch; Runs; Crews; CrewAI reports; Categories; Skills `/admin/automation/skills`; **Configuration** `/admin/crewai/config`, which has its own tabs Overview, Repository, Import / export, History and **Settings** (the GitHub repository and token)
  - *Content*: **Content sources** (the "Fetching" settings card); Topics; Profiles & playground (writing and image profiles; each image profile has its own image provider); Content analytics; Keywords; Recommendations; Content audit; Internal linking
  - *Traffic*: Search performance; Visitor analytics; Page insights; SEO-AI reports
  - *Authority & health*: Backlinks; AI visibility; Technical health
  - *Models & data*: **ML models** `/admin/models` (an override per model); Article index
  - *Settings*: **Settings** `/admin/automation`, a sectioned shell (`?section=`) with 14 sections under 4 headings:
    - SEO agent: Overview (SEO agent endpoint card and connection status) · Agent limits (agent group `agent-limits` and `news` "Content flow limits") · Run history (`seo.runHistory` and `news` logs)
    - Models & AI: LLM providers & budget (agent budget, agent providers, Claude usage) · AI & drafts (`seo.drafts`, `seo.llm`, `seo.aiVisibility`, `news` models and quality gates) · ML & retrieval (ML card, agent groups `retrieval` and `embeddings`, `news` ranking)
    - Assistants: Ask the Blog (`ask_blog`) · MCP (status, connected clients, agent group `mcp` drawn as "Server settings")
    - SEO: Data sources · Schedules · Scoring & rules · Content & links · Crawler · Reports (all from the `seo` document)
  - **MCP** → `/admin/automation?section=mcp`, the same page as above
- **Billing** (admin) → Invoices `/admin/invoices`, with a **Settings** button to `/admin/invoices/settings` (not in the menu); **Payments** `/admin/payments` (the "Razorpay payments" settings card)
- **Practice** → Python practice `/admin/practice`. Its last card, **Settings**, is admin-only and holds 24 settings.
- **Appearance** (admin)
  - **Customise** `/admin/appearance`: the Appearance editor, a client-side sectioned shell with draft, preview, Publish and history. 13 sections: General · Branding · Header · Navigation · Footer · Typography & colours · Homepage · Blog & articles · Media · SEO & integrations · Hire me · Advanced · Revision history (with Import/export)
  - Menus → `?section=navigation`; Homepage → `?section=homepage`; Typography & colours → `?section=theme`
- **Users** (shown as "Your account" to authors) → **All users** `/admin/users` (admin; the role per user and, at the end of the page, the "Members-only articles" and "Profile pictures" cards); **Profile** `/admin/profile`; **API keys** `/admin/api-keys`
- **Tools** (admin) → Site health `/admin/system`; **Cache** `/admin/cache` (the "Cloudflare" card and the "Cloudflare settings" runtime group); **Backups (export / import)** `/admin/backups` (schedule, encryption and bucket); Data sync; Database; Audit log
- **Settings** (admin)
  - **General** → `/admin/appearance?section=general`. This is the Appearance editor, so a change waits for Publish.
  - **Integrations** `/admin/integrations`, a server sectioned shell with 11 sections: Social sign-in · Turnstile · IndexNow · Search engine verification · Analytics & ads · Search Console & GA4 (status only, no fields) · Image generation · Image limits · Video generation · Hybrid RAG · SEO agent
  - **Media & storage** `/admin/storage`, a sectioned shell: Media storage · Video destinations · Move media to R2 (shown only while there is something to move)
  - **Email** `/admin/email`, a sectioned shell: Provider · Test message
- **Help** (foot of the menu) → User manual `/admin/user-manual`, with the Guides, FAQ and Settings reference tabs

**Pages that use the sectioned settings shell** (`components/admin/SettingsSections.tsx`):
- Appearance uses the client-state variant (`onSelect`).
- Integrations, Media & storage, Email and AI & SEO → Settings use the server variant (`basePath`, `?section=`).
- These pages have settings but no shell: Users, Cache, Payments, Bookings, Backups, Invoices → Settings, Practice, Promotion, Profile. CrewAI Configuration uses its own `?tab=` tabs.
